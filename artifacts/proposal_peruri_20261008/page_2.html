2. Latar Belakang & Rumusan Masalah (Problem Statement)

Latar Belakang:

Identitas dan dokumen digital memerlukan integritas isi serta autentikasi penandatangan. SHA-256 menghasilkan digest pesan, sedangkan ECDSA mengikat digest tersebut pada pemilik private key [2–4]. PURI-Sign memusatkan operasi signing dan penggunaan key dalam core hardware. Host tetap bertanggung jawab atas hashing dokumen, otorisasi aplikasi, dan provisioning key yang aman.

Baseline Tiny Tapeout SHA-256 [1] menjadi referensi awal pengembangan. Cakupan implementasi yang dievaluasi pada proposal ini adalah core signing ECDSA P-256 256-bit, bukan mesin verification-only atau klaim kompatibilitas TT07 yang belum diuji pada build ini.

Rumusan Masalah & Perancangan:

Desain awal menduplikasi mesin ECC pada key_manager dan ecdsa_signer, sehingga melampaui kapasitas target. Tantangannya adalah mengurangi penggunaan logika tanpa mengurangi lebar operand atau fungsi ECDSA, menjaga isolasi akses key dan pembatalan operasi, serta membedakan hasil implementasi dari target pengujian board dan ASIC.

3. Proposed Chip Design

3.1 Solusi & Arsitektur Sistem

Host → register Avalon-MM → FSM tinysign_core → key_manager / ecdsa_signer → engine ECC bersama → register public key atau signature.

FSM perintah menetapkan owner PROVISION atau SIGN. Satu scalar_mult, satu mod_inv, dan satu mod_mul pada level core melayani kedua controller secara bergantian. Total multiplier seluruh hierarki turun dari delapan menjadi empat; RFC6979/HMAC tetap satu instance pada signer. Sharing mempertahankan urutan komputasi karena provisioning dan signing memang tidak berjalan bersamaan.

Alur penggunaan: tulis key d → PROVISION menghitung Q=dG → LOCK → tulis digest → SIGN → periksa BUSY/DONE/ERROR → baca (r,s). Readback private key bernilai nol. ZEROIZE dapat menyela operasi, membersihkan key dan state, lalu membuka kembali tahap provisioning. Key disimpan dalam register volatil; proteksi fisik dan ketahanan side-channel belum dibuktikan.
